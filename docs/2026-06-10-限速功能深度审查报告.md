## 🔴 严重问题详述

### BUG-1：UDP 带宽限速 `WaitN` 在 packet > burst 时静默丢包

**文件**：`internal/tunnel/udp.go:192-196`、`udp.go:217-221`

**问题**：`rate.Limiter.WaitN(ctx, n)` 当 `n > burst` 时直接返回错误（不等待）。UDP 报文最大 64KB，当用户配置小带宽（如 100KB/s，默认 burst=100KB）时，任何大于 burst 的报文都会被丢弃。TCP/HTTP 路径用了 `counting.go` 的 `waitBurst` 正确做了分块，UDP 漏了。

**修复**：两处 `bwLimiter.WaitN(...)` 改为 `waitBurst(...)`。

**状态**：✅ 已修复（`internal/tunnel/udp.go`）

---

### BUG-2：API 限速不读 `X-Forwarded-For`

**文件**：`internal/ratelimit/api_limiter.go:127-133`（`remoteIP` 函数）

**问题**：只用 `r.RemoteAddr`，不读 `X-Forwarded-For` / `X-Real-IP`。部署在 Nginx/Traefik/Caddy 之后时，所有请求来自反向代理 IP → perIP 限速退化为全局单 IP 限速，所有用户共享同一桶。

**修复方案**：
1. `APIRateLimitConfig` 新增 `TrustedProxies []string`（CIDR 格式）
2. `APILimiter` 新增 `trustedNets []*net.IPNet`
3. `remoteIP` 改为方法，当 RemoteAddr 匹配可信代理时从 `X-Forwarded-For` 取最右非可信 IP
4. 新增 `parseTrustedProxies` 解析 CIDR/纯 IP

**状态**：✅ 配置字段已添加（`internal/ratelimit/config.go`），`api_limiter.go` 重写已完成

---

### BUG-3：HTTP/WS 连接限速拒绝时不记日志

**文件**：`internal/tunnel/http.go:219-220`、`http.go:284-286`

**问题**：`handleHTTPProxy` 和 `handleWebSocketGateway` 中 `AcquireConn` 返回 false 时直接返回 HTTP 429，不记 `slog.Warn`。TCP/UDP 都有日志，HTTP/WS 没有，线上无法定位哪个隧道、哪个客户端被限流。

**修复**：补 `slog.Warn("HTTP/WS connection limit exceeded", "tunnel", tunnelName, "nodeId", node.ID, "remote", r.RemoteAddr)`。

**状态**：✅ 已修复（`internal/tunnel/http.go`）

**文件**：`internal/tunnel/http.go:307`

**问题**：`r.Write(stream)` 直接写裸 stream，未经过 `countingConn` 包装。攻击者可发巨型 Upgrade 头绕过带宽限制。HTTP 代理路径 `r.Write(trackedStream)` 是限速的，行为不一致。

**修复方案**：在 `handleWebSocketGateway` 中，OpenStream 之后先用 `countingConn` 包装 stream 用于升级写入：
```go
upgradedStream := &countingConn{
    Conn:      stream,
    ctx:       r.Context(),
    bwLimiter: tg.limiter.BWLimiterFor(sKey),
}
if err := r.Write(upgradedStream); err != nil { ... }
br := bufio.NewReader(stream) // 后续读取继续用裸 stream
```

**状态**：✅ 已修复（`internal/tunnel/http.go`）

### BUG-5：`NopLimiter.EffectiveLimits` 返回 `{0,0}` 语义歧义

**文件**：`internal/ratelimit/limiter.go:7-8`

**问题**：前端拿到 `effective_max_conns=0, effective_max_bandwidth=0` 无法区分"限速关 → 不限速"和"限速开但配置为 0 → 拒绝/不限速"。

**修复**：在 `EffectiveLimits` struct 注释中明确 `0 = unlimited` 语义。

**状态**：✅ 已修复（`internal/ratelimit/limiter.go`）

---

### BUG-6：32-bit 平台 `int(bps)` 默认 burst 溢出

**文件**：`internal/ratelimit/conn_limiter.go:90-93`

**问题**：`MaxBandwidthPerTunnel` 是 `int64`，默认 burst 直接 `int(bps)`。32-bit 平台 `int` 最大 ~21 亿，bps > 2^31-1 时溢出为负数。Go 1.25 主流 64-bit 暂不受影响，但 ARM/Linux embedded 可能踩坑。

**修复**：新增 `safeBurst(bps int64) int` 函数，在 `MaxInt` 处截断。

**状态**：✅ 已修复（`internal/ratelimit/conn_limiter.go`）

---

### BUG-7：`TotalConns` 包含失败的连接尝试

**文件**：`internal/tunnel/tcp.go:80-81`

**问题**：`ConnOpened` 在 `AcquireConn` 成功后、`GetSession`/`OpenStream` 之前调用。如果后者失败，`TotalConns` 被错误累加。语义不清晰（"总连接尝试" vs "总成功连接"）。

**修复方案**：将 `ConnOpened` 移到 `OpenStream` 成功之后。

**状态**：✅ 已修复（`internal/tunnel/tcp.go`）

**文件**：`internal/service/tunnel_service.go:612-618`

**问题**：`for _, t := range node.Tunnels` 浅拷贝 Tunnel，`Para json.RawMessage`（`[]byte`）与原始共享底层。当前 loop 不修改 Para 所以安全，但任何未来修改都会静默污染源数据。

**评估**：当前安全，标记为已知风险。

**状态**：❌ 无需修复（当前不改 Para）

---

### BUG-9：节点断连时 in-flight conn 计数与新请求交错

**文件**：`internal/ratelimit/conn_limiter.go:155-187`

**问题**：`RemoveTunnel` 删除 `tunnelConns[sKey]`，但 in-flight conn 的 `defer ReleaseConn` 会在 key 不存在时 no-op。严格时序下：旧 conn A 持有计数 → RemoveTunnel 清零 → 新 conn B 进入（计数=1）→ A 的 defer -1 给了 B 的计数（B 还没关就显示 conn=0）。需要 connMu 互斥保护（已实现），但 A 的 Release 可能错误扣减 B 的计数。

**修复方案**：引入 `generation` 令牌机制，`AcquireConn` 返回 generation，`ReleaseConn` 校验。

**状态**：✅ 已修复（`internal/ratelimit/conn_limiter.go`）

## 🟠 设计 / 一致性问题

### BUG-10：健康检查端点被 per-IP 限速

**文件**：`internal/api/router.go:94-97`

**问题**：`r.limiter.Middleware(core)` 在最外层，`/api/v1/health` 在 `loggingMiddleware` 中跳过日志但不跳过限速。高频监控轮询会打满 perIP 桶，触发 429 → 监控告警误报。

**修复方案**：在 `Build()` 中，健康检查路径绕过限速中间件：
```go
if r.limiter != nil {
    mw := r.limiter.Middleware(core)
    core = http.HandlerFunc(func(w http.ResponseWriter, req *http.Request) {
        if req.URL.Path == "/api/v1/health" {
            core.ServeHTTP(w, req)
            return
        }
        mw.ServeHTTP(w, req)
    })
}
```

**状态**：✅ 已修复（`internal/api/router.go`）
