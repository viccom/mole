# 安全与质量修复 R2 实施计划（审查报告遗留 🟡/🟢 项批量收口）

> **基线**：叠加于 `fix/security-r1`（分支 `fix/quality-r2`）；客户端叠加于 `feat/proof-auth`（分支 `fix/bounded-read`）。全程 TDD、不合并主线。

## 修复范围（按价值/风险筛选）

### A 组：API / 认证 / 用户（SEC-08、SEC-14、QUA-06、QUA-07、QUA-12、QUA-02、REL-07、DOC-01）
- **SEC-08** `resetPassword` 提权：重置他人密码改为要求 `users:admin` 权限（handler 内校验，自助改密走 /auth/changepass 不受影响）；README 权限表同步（DOC-01）
- **SEC-14** `ChangePassword` 补口令强度校验（复用 Create/Update 路径的既有校验函数）
- **QUA-06** 登录时序防枚举：用户不存在时也执行一次等效 bcrypt（dummy hash 比较）
- **QUA-07** `setStatus` 状态白名单（active/disabled/locked 之类，以 core 常量为准）
- **QUA-12** OPTIONS 预检直接 204 返回，不执行真实 handler（router 层）
- **QUA-02**（API 侧）handler 直接回传 `err.Error()` 的位置统一脱敏：对外 generic 消息，细节进日志
- **REL-07** 删除用户级联：`user_repo` 级联删除错误不再吞（上抛）；handler 级联失败返回 500 并记日志（不引入事务，Redka KV 无事务）
- **DOC-01** README 权限标注与本批最终语义对齐

### B 组：隧道核心（REL-01、02、03、04、06、PERF-01、QUA-01、QUA-11、QUA-02）
- **REL-01** `validateTunnel` 增加 listen_port 校验：范围 1-65535、不落在服务自身保留端口（9980/9981/9982/9983/1882/1883）、服务全局唯一；`applyRuntimeTunnels` 监听失败回滚旧监听器并回传 `ErrPortInUse`（不再静默继续）
- **REL-02** register 携带隧道列表过 `validateTunnels` + 条数上限 256，失败拒绝注册
- **REL-03** UDP 会话回插 CAS：`sessions[key]` 已有并发会话时关闭败者并释放其资源
- **REL-04** UDP 建会话接入 `tg.sem`（max_concurrent），会话关闭/过期时释放
- **REL-06** `probeOldSession` 判死阈值 3s→8s（探针本身已幂等：推送的就是该节点现存隧道；不引入新协议命令——客户端对未知命令静默忽略，新探针对旧客户端会误判）
- **PERF-01** `biCopy` 缓冲改 `sync.Pool`（尺寸维持 1MB 或降为 256KB 按实测定，给出选择依据）
- **QUA-01** `RebuildIndex` 双索引单锁原子替换（快照构造后一次换入）
- **QUA-11a** `connectionWorker` 的 `connChan` 在 ControlServer 关闭时 close（优雅退出；smux 32MB 缓冲不动——行为变更风险大）
- **QUA-02**（control 侧）register/控制命令路径错误回传脱敏

### C 组：基础设施（SEC-09、SEC-13、REL-05、REL-08、QUA-04、QUA-09）
- **SEC-09** MQTT Publish API 补 topic 归属校验：非 admin 身份按 `aclHook` 同规则校验 `/mole/<nodeId>/...` 归属
- **SEC-13** 控制端口认证失败 per-IP 限速（复用 login_limiter 模式：10 失败/5 分钟锁 5 分钟，默认启用）
- **REL-05** `gatewaySrv` 补 `ReadHeaderTimeout: 10s` + `IdleTimeout: 120s`（不设短 ReadTimeout——WebSSH 长连接）
- **REL-08** HTTP 代理剔除 hop-by-hop 头（Connection/Keep-Alive/Transfer-Encoding 等，含 Connection 声明的逐跳头）；HTTPS 类型域名路由与 HTTP 类型统一（评估 registry/findNodeTunnel 的类型集合后对齐）
- **QUA-04** 死代码清理：确认无调用方后删除 `RegisterHTTP`、`setGrant/getGrant`、`age()`（编译器验证）
- **QUA-09** `aclHook` 在 `rbac == nil` 时 fail-closed（拒绝 + WARN 日志；生产必接 rbac，nil 仅测试场景）

### D 组：客户端（PROTO-02）
- `handleServerCmd` 读行加上限（对齐服务端 readBoundedLine 思路：上限 1MB，超限断开），防故障/恶意服务端内存尖峰

## 明确暂缓（含理由，供后续决策）
| 项 | 理由 |
|----|------|
| SEC-10 HttpOnly/CSRF/query token | 需改前端认证流（跨组件破坏性），需产品侧配合 |
| SEC-11 MQTT TLS | 部署特性，需证书供应与运维配套 |
| SEC-12 tunnel_secret 强制 | 存量部署升级即拒启，需运维窗口决策 |
| QUA-05 登出/会话吊销 | 需会话存储设计（与 jti/refresh 联动），独立议题 |
| QUA-03 MaxNodes 生效 | 行为变更（默认无上限→有限），默认值需产品定 |
| QUA-10 JWT iss/aud/jti | 无吊销机制前价值有限，与 QUA-05 同议题 |
