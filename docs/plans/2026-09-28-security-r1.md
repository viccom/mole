# 安全修复 R1 实施计划（SEC-01~07 一次性修复 + 双格式过渡 + 端到端矩阵）

> **执行方式**：主会话编排（hub-and-spoke），实现任务派发子代理，每个任务 TDD（先红后绿，回报真实输出证据）；主会话审查 diff 与证据。全程不合并主线。

**目标**：修复审查报告全部 7 个 🔴 严重问题，采用 2+1 升级结构（服务端 R1 双格式过渡版 → 客户端升级一次 → 服务端 R2 配置收口），并完成新旧版本端到端矩阵实测。

**架构**：
- 服务端 R1 分支 `fix/security-r1`（基于 master @ 7d6fdb9）：全部 7 项修复生效；节点认证同时接受旧格式 `{"token"}` 与新格式 `{"proof"}`；新增配置开关 `node_auth.legacy_format_enabled`（默认 true）与 `node_auth.register_owner_check`（默认 true）。
- 客户端分支 `feat/proof-auth`（基于 master @ 6816da8）：认证改为 proof 格式（only 新格式，无回落），其余行为不变。
- R2 收口 = 仅改配置 `legacy_format_enabled: false` 重启，不发版。

**新认证协议（SEC-01 定稿）**：
- 服务端发 32 字节随机 challenge（不变）。
- 客户端：`h = sha256(token)`（原始 32 字节 digest）；`proof = hex(HMAC-SHA256(key=h[:], msg=challenge))`；发送 `{"proof":"<hex>"}\n`。**不带任何标识符**。
- 服务端：遍历全部 active access token，对每个候选以 `decode_hex(TokenHash)` 为 key 复算 HMAC 并常量时间比对；legacy 全局 token 作为追加候选（key = `sha256(legacyPlaintext)` 原始字节）；命中即认证通过（TouchLastUsed 同旧路径）；无命中返回与旧路径一致的错误。
- 防重放/防嗅探：proof 绑定一次性 challenge；嗅探者拿不到 key（sha256 单向、digest 不上线）。
- 已知边界：低熵 token 理论上可离线穷举 proof——mat_ token 为 32 字节随机 hex（256 bit），不受影响；legacy 弱口令由 R2 弃用收口。

## 服务端任务（moleAgent_Serv @ fix/security-r1）

### S1（SEC-04）：RefreshToken 回库重查角色
- 文件：`internal/auth/service.go:96-112`
- 实现：复查用户状态后，仿照 `Login`（:57-66 附近）调 `s.rbac.GetUserRoles(claims.UserID)` 重建 `claims.Roles` 再 `GenerateToken`。
- 测试（先红）：撤销/新增角色后 refresh，解析新 JWT 验证 roles 为最新值。

### S2（SEC-03）：Node.Token 停存停回显
- 文件：`internal/api/node_handler.go`（Get 单节点/Create 响应）、`internal/service/tunnel_service.go:918-924`（persistableNode）、`internal/tunnel/control.go` persistNode（如有独立路径）
- 实现：响应前与落库前统一 `Token = ""`（json omitempty 使字段整体消失）。
- 测试：GET /nodes/{id} 响应无 token 字段；持久化 JSON 无 token 字段。

### S3（SEC-06）：AccessKey 旁路收窄
- 文件：`internal/auth/middleware.go`、`internal/api/router.go:31`、`cmd/moleagent-serv/main.go:493,533-535,539`
- 实现：新增 `RequirePermissionNoAccessKey`（闭包内对 `UserID=="access_key"` 直接 403）与 `RegisterStrict` 路由变体；切换 5 条路由：DELETE /users/、GET/PUT/DELETE /api/v1/accesskey、POST /api/v1/self-update。其余路由维持原旁路。
- 测试：带有效 W-Access-Key 访问 strict 路由 → 403；访问普通路由 → 正常。

### S4（SEC-07）：登录独立限速
- 文件：新增 `internal/auth/login_limiter.go`；接线 `cmd/moleagent-serv/main.go:457`
- 实现：per-IP + per-用户名失败计数（默认 10 次/5 分钟窗口，锁 5 分钟），成功登录清零；**不随 `ratelimit.api.enabled` 总开关关闭**；超限返回 429。
- 测试：连续错误密码 11 次 → 第 11 次 429；窗口内正确密码也被锁；窗口过后恢复（测试用可注入时钟或短窗口）。

### S5（SEC-05）：默认凭据安全化
- 文件：`internal/config/config.go:331-342`、`internal/storage/db.go:122-175`、`cmd/moleagent-serv/main.go:154-163`
- 实现：
  - admin 密码：MA_ADMIN_PASS 未设且落库哈希仍等于默认 "admin"（bcrypt 比对）→ 生成随机强口令并打印 stderr 一次；MA_ADMIN_PASS 已设 → 修复路径扩展为"哈希缺失或仍为默认"时用环境值重建（无缝换密通道）。
  - 节点 token：env/flag 均未设 → **拒绝启动**（替换现有 WARN），错误信息给出配置指引。
- 测试：随机口令生成（非空、熵）；默认口令哈希触发轮换；节点 token 缺失时启动函数返回错误。

### S6（SEC-02）：register 归属校验
- 文件：`internal/tunnel/control.go:718-748`、config 接线
- 实现：格式校验后、节点构造前，`GetByID(cmd.NodeID)`；若持久记录存在且 `OwnerUserID != "" && OwnerUserID != grant.UserID && grant.UserID != "system"` → 回 `err` 并关闭（WARN 记录 nodeId/grantUser/persistedOwner）。配置 `node_auth.register_owner_check: false` 可跳过（kill-switch）。
- 测试（覆盖 5 分支）：异主拒绝 / 同主通过 / system 归属通过（兼容 legacy 时代记录）/ legacy grant(system) 通过 / kill-switch 关闭通过。

### S7（SEC-01）：双格式认证（服务端侧）
- 文件：`internal/core`（NodeAccessAuthenticator 接口）、`internal/service/node_access_auth.go`、`internal/tunnel/control.go:360-384`、配置接线至 ControlServer
- 实现：
  - 接口新增 `AuthenticateNodeProof(ctx, proofHex string, challenge []byte) (*NodeAccessGrant, error)`；实现按上文协议（tokenRepo 需列举能力，缺则补 List 方法；全部候选常量时间比对）。
  - control.go 解析 `struct{Token, Proof string}`：Proof 非空走 proof 路径；否则 Token 非空且 `legacy_format_enabled`（默认 true）走旧路径，开关关闭时拒绝；两者皆空 → invalid。
- 测试：proof 往返验证（客户端式计算 vs 服务端校验）通过；challenge 错一位失败；开关关闭后旧格式被拒、proof 格式不受影响；所有现有测试适配新接口签名。

## 回滚与不可逆点

- 全程分支开发，master 不动；任一阶段可 `git checkout master` 完整回退。
- 不可逆点仅在"生产客户端开始批量升级"后（proof-only 客户端不兼容旧服务端）；回滚目标只能是 R1，不能是 v0.6.x。
- SEC-05 对存量默认口令部署会强制换密——上线前预置 MA_ADMIN_PASS（运维须知，已在本计划外沟通）。
