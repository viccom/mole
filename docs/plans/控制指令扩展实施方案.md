# 控制指令扩展实施方案

> 分支：`feature/control-ext`
> 状态：待实施
> 原则：最小侵入，向后兼容，不破坏现有功能

## 0. 范围

| # | 指令 | 方向 | 优先级 | 说明 |
|---|------|------|--------|------|
| 1 | 增强 `ping` | 双向 | P2 | 携带时间戳，测量 RTT |
| 2 | `sysinfo` | C→S | P2 | 客户端上报系统信息 |
| 3 | `tunnel_status` | C→S | P0 | 客户端上报隧道运行时状态 |
| 4 | `tunnel_action` | S→C | P1 | 服务端远程启停/重启隧道 |
| 5 | `restart` | S→C | P3 | 服务端请求客户端优雅重启 |

**排除**：`health_check`（P1）不实施。

---

## 1. 现状分析

### 1.1 共享协议结构

```
客户端 protocol.ControlCmd:  {cmd, node_id, name, token, tunnels}
服务端 tunnel.ControlCmd:    {cmd, node_id, name, token, tunnels}  (独立定义，字段相同)
客户端 protocol.ControlResponse: {cmd, msg}
服务端 tunnel.ControlResponse:   {cmd, msg}
```

**问题**：两端 ControlCmd/ControlResponse 是独立定义的重复结构，但字段名和 JSON tag 一致，扩展时需同步修改两处。

### 1.2 服务端 handleStream（3 个 case）

```go
switch cmd.Cmd {
case "register":    cs.handleRegister(...)
case "ping":        // 更新 LastHeartbeat, 回 pong
case "tunnel_update": cs.handleTunnelUpdate(...)
default:            writeControlResp(stream, "err", "unknown command")
}
```

### 1.3 客户端 dispatchStream（首字节启发式）

```
'{': handlePossiblePush() — 仅识别 tunnel_push
'\x00': TCP/UDP 代理
'\x01': WebSSH 代理
HTTP: HTTP 代理
fallback: 原始转发
```

### 1.4 S→C 推送模式（PushTunnelUpdate）

```go
session.OpenStream() → json.Marshal(cmd) → Write(append(data, '\n'))
→ SetReadDeadline(10s) → Read → json.Unmarshal(resp)
```

### 1.5 Manager 已有能力

| Manager | Status(name) | List() | Start/Stop |
|---------|-------------|--------|------------|
| ser2mq | `Ser2MQStats{Running, SerialOpen, MQTTConnected, BytesIn, BytesOut, Error}` | 有 | `Create(name, cfg)` / `Stop(name)` |
| vpn | `Status{Running, PID, StartTime, CrashCount, Error}` | 有 | `Start(name)` / `Stop(name)` |
| ser2net | `Stats{Running, SerialOpen, Clients, BytesIn, BytesOut}` | 有 | 无直接 Start/Stop |
| webssh | `Stats{Running, Sessions, BytesIn, BytesOut}` | 有 | 无直接 Start/Stop |

**关键发现**：所有 Manager 已有 `Status()` 和 `List()` 方法，数据结构完备，无需新建。

## 2. 设计原则

1. **所有新字段 `omitempty`** — 旧版本忽略未知字段，新版本检测 `ts == 0` 或 `statuses == nil` 判断对方是否支持
2. **不修改已有 case 行为** — register/ping/tunnel_update 的处理逻辑不变
3. **S→C 命令复用 PushTunnelUpdate 模式** — 新建 `sendToNode()` 通用方法
4. **客户端 S→C 分发统一入口** — `handlePossiblePush` 重命名为 `handleServerCmd`，内部按 `cmd.Cmd` switch
5. **Manager 通过已有 Status() 方法收集数据** — 不引入新接口

### Phase 2：增强 ping + sysinfo（C→S，最简单）

#### 3.2.1 增强 ping

**客户端** `client.go` — `sendPing()` 方法：

```go
// 改动前
cmd := protocol.ControlCmd{Cmd: "ping"}

// 改动后
cmd := protocol.ControlCmd{Cmd: "ping", Ts: time.Now().UnixMilli()}
```

收到 pong 后计算 RTT：

```go
if resp.Ts > 0 {
    rtt := time.Now().UnixMilli() - resp.Ts
    // 可通过 EventBus 暴露 RTT，或存储到 Client 字段
    c.events.Emit(Event{Type: EventRTT, Data: map[string]any{"rtt": rtt}})
}
```

**服务端** `control.go` — ping case：

```go
case "ping":
    node := state.get()
    if node != nil {
        cs.nodeMgr.Update(ctx, node.ID, func(n *core.Node) {
            now := time.Now()
            n.LastHeartbeat = &now
            if cmd.Ts > 0 {
                n.RTT = time.Now().UnixMilli() - cmd.Ts
            }
        })
    }
    writeControlRespTs(stream, "pong", "", cmd.Ts) // 原样回传 ts
```

新增 `writeControlRespTs` 辅助函数（或修改 `writeControlResp` 增加 ts 参数）。

**兼容性**：旧客户端不发 ts → cmd.Ts == 0 → 不计算 RTT。旧服务端不回 ts → resp.Ts == 0 → 客户端跳过。

### Phase 3：tunnel_status（C→S，P0）

#### 3.3.1 客户端 — 收集各 Manager 状态

新增 `collectTunnelStatuses()` 方法，利用已有 Manager.Status() 和 Manager.List()：

```go
func (c *Client) collectTunnelStatuses() []protocol.TunnelStatus {
    c.mu.RLock()
    tunnels := c.tunnels
    c.mu.RUnlock()

    statuses := make([]protocol.TunnelStatus, 0, len(tunnels))
    for _, t := range tunnels {
        st := protocol.TunnelStatus{
            Name: t.Name,
            Type: string(t.Type),
        }
        switch t.Type {
        case TunnelTypeSer2MQ:
            if stats, err := c.ser2mqMgr.Status(t.Name); err == nil {
                st.Running = stats.Running
                st.Connected = stats.MQTTConnected && stats.SerialOpen
                st.SerialOpen = stats.SerialOpen
                st.MQTTConnected = stats.MQTTConnected
                st.BytesIn = stats.BytesIn
                st.BytesOut = stats.BytesOut
                st.Error = stats.Error
            }
        case TunnelTypeSer2TCP, TunnelTypeSer2UDP:
            if stats, err := c.ser2netMgr.Status(t.Name); err == nil {
                st.Running = stats.Running
                st.Connected = stats.SerialOpen
                st.SerialOpen = stats.SerialOpen
                st.Clients = stats.Clients
                st.BytesIn = stats.BytesIn
                st.BytesOut = stats.BytesOut
            }
        case TunnelTypeVPNMgr:
            if stats, err := c.vpnMgr.Status(t.Name); err == nil {
                st.Running = stats.Running
                st.Connected = stats.Running
                st.PID = stats.PID
                if stats.StartTime > 0 {
                    st.UptimeSeconds = time.Now().Unix() - stats.StartTime
                }
                st.Error = stats.Error
            }
        case TunnelTypeHTTP, TunnelTypeHTTPS, TunnelTypeTCP, TunnelTypeUDP:
            st.Running = true // 代理层隧道由服务端管理，客户端侧始终 running
            st.Connected = true
        case TunnelTypeWebSSH:
            if stats, err := c.websshMgr.Status(t.Name); err == nil {
                st.Running = stats.Running
                st.Connected = stats.Running
            }
        }
        statuses = append(statuses, st)
    }
    return statuses
}
```

### Phase 4：tunnel_action（S→C，P1）

#### 3.4.1 服务端 — 通用 S→C 命令发送

`PushTunnelUpdate` 的发送模式可以泛化。新增通用方法 `sendToNode`：

```go
// sendToNode 向指定节点发送命令并等待响应
func (cs *ControlServer) sendToNode(ctx context.Context, nodeID string, cmd ControlCmd, timeout time.Duration) (*ControlResponse, error) {
    session, err := cs.nodeMgr.GetSession(ctx, nodeID)
    if err != nil {
        return nil, err
    }
    stream, err := session.OpenStream()
    if err != nil {
        return nil, fmt.Errorf("open stream: %w", err)
    }
    defer stream.Close()

    data, err := json.Marshal(cmd)
    if err != nil {
        return nil, fmt.Errorf("marshal: %w", err)
    }
    if _, err := stream.Write(append(data, '\n')); err != nil {
        return nil, fmt.Errorf("send: %w", err)
    }

    buf := make([]byte, 4096)
    stream.SetReadDeadline(time.Now().Add(timeout))
    n, err := stream.Read(buf)
    if err != nil {
        return nil, fmt.Errorf("read response: %w", err)
    }

    var resp ControlResponse
    if err := json.Unmarshal(buf[:n], &resp); err != nil {
        return nil, fmt.Errorf("parse response: %w", err)
    }
    return &resp, nil
}
```

`PushTunnelUpdate` 可重构为调用 `sendToNode`（或保留不变，避免影响稳定代码）。

`tunnel_action` 执行逻辑：

```go
func (c *Client) handleTunnelAction(stream *smux.Stream, name, action string) {
    c.mu.RLock()
    var tunnelType string
    for _, t := range c.tunnels {
        if t.Name == name {
            tunnelType = string(t.Type)
            break
        }
    }
    c.mu.RUnlock()

    var err error
    switch tunnelType {
    case "vpn-manager":
        switch action {
        case "start":
            err = c.vpnMgr.Start(name)
        case "stop":
            err = c.vpnMgr.Stop(name)
        case "restart":
            c.vpnMgr.Stop(name)
            err = c.vpnMgr.Start(name)
        }
    case "ser2mq":
        // ser2mq 通过 OnTunnelUpdate 控制生命周期
        // stop: 从 configs map 中移除 → OnTunnelUpdate
        // start: 重新传入 config → OnTunnelUpdate
        // 这里需要从当前 tunnels 中找到 config 并调用 OnTunnelUpdate
        switch action {
        case "stop":
            c.mu.RLock()
            configs := c.buildSer2MQConfigs()
            delete(configs, name)
            c.mu.RUnlock()
            c.ser2mqMgr.OnTunnelUpdate(configs)
        case "start", "restart":
            c.mu.RLock()
            configs := c.buildSer2MQConfigs()
            c.mu.RUnlock()
            c.ser2mqMgr.OnTunnelUpdate(configs)
        }
    case "ser2tcp", "ser2udp":
        // 类似 ser2mq
        switch action {
        case "stop":
            c.mu.RLock()
            configs := c.buildSer2NetConfigs()
            delete(configs, name)
            c.mu.RUnlock()
            c.ser2netMgr.OnTunnelUpdate(configs)
        case "start", "restart":
            c.mu.RLock()
            configs := c.buildSer2NetConfigs()
            c.mu.RUnlock()
            c.ser2netMgr.OnTunnelUpdate(configs)
        }
    default:
        err = fmt.Errorf("action not supported for type: %s", tunnelType)
    }

    if err != nil {
        resp, _ := json.Marshal(map[string]string{"cmd": "err", "msg": err.Error()})
        stream.Write(resp)
    } else {
        resp, _ := json.Marshal(map[string]string{"cmd": "ok", "msg": action + " done"})
        stream.Write(resp)
    }
}
```

需要新增辅助方法 `buildSer2MQConfigs()` 和 `buildSer2NetConfigs()`，从当前 tunnels 中提取对应类型的配置 map。

**验收**：
- `POST /api/v1/tunnels/vpn-office/action {"action":"stop", "node_id":"..."}` 远程停止 VPN
- `POST /api/v1/tunnels/vpn-office/action {"action":"start", "node_id":"..."}` 远程启动 VPN
- 不支持的类型返回 `"action not supported for type: http"`

### Phase 5：restart（S→C，P3）

#### 3.5.1 服务端 API

func (s *TunnelConfigService) RestartNode(ctx context.Context, nodeID string, delay int, reason string) error {
    cmd := ControlCmd{
        Cmd:    "restart",
        Delay:  delay,
        Reason: reason,

#### 3.5.2 客户端处理

```go
func (c *Client) handleRestart(stream *smux.Stream, delay int, reason string) {
    resp, _ := json.Marshal(map[string]string{"cmd": "ok", "msg": fmt.Sprintf("restarting in %ds", delay)})
    stream.Write(resp)

    log.Printf("Server requested restart (delay=%ds, reason=%s)", delay, reason)
    time.Sleep(time.Duration(delay) * time.Second)

    // 优雅关闭
    c.ser2mqMgr.Close()
    c.ser2netMgr.Close()
    c.vpnMgr.Close()
    c.websshMgr.Close()
    c.transport.Close()
    os.Exit(0)
}
```

**验收**：`POST /api/v1/nodes/{id}/restart` 触发客户端延迟后优雅退出，systemd 自动重启。

## 5. 兼容性矩阵

| 场景 | 客户端行为 | 服务端行为 |
|------|-----------|-----------|
| 新客户端 + 旧服务端 | ping 发 ts，旧服务端忽略 ts 字段，pong 无 ts → 客户端跳过 RTT | — |
| 旧客户端 + 新服务端 | 不发 ts/sysinfo/tunnel_status → 服务端字段为空/nil | — |
| tunnel_action 到旧客户端 | — | 旧客户端收到未知 cmd → 返回 `{"cmd":"err","msg":"unknown command"}` → 服务端提示不支持 |
| restart 到旧客户端 | — | 同上 |

## 6. 实施顺序与依赖

```
Phase 1 (协议扩展) ──→ Phase 2 (增强 ping + sysinfo)
                    ──→ Phase 3 (tunnel_status)
                    ──→ Phase 4 (tunnel_action) — 依赖 Phase 3 的 sendToNode
                    ──→ Phase 5 (restart) — 复用 Phase 4 的 sendToNode
```

Phase 1 → 2 → 3 可串行实施并逐个验证。Phase 4 和 5 可并行开发（都依赖 Phase 1 + sendToNode）。

## 7. 测试要点

1. **增强 ping**：验证新旧客户端/服务端互操作，RTT 计算准确性
2. **sysinfo**：验证 register 附带 + 心跳周期上报，API 返回完整数据
3. **tunnel_status**：验证各类型隧道状态收集准确性，配置变更后即时上报
4. **tunnel_action**：验证 vpn-manager start/stop/restart，ser2mq stop/start，不支持类型返回错误
5. **restart**：验证延迟退出，优雅关闭所有隧道
6. **回归**：现有 register/ping/tunnel_update/tunnel_push 流程不受影响
